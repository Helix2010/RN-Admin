# 管理端反馈与校验交互规范

本规范适用于 RN-Admin 的配置、发布、上传、连接测试和普通表单操作。

## 反馈类型与位置

| 场景                                 | 展示位置           | 行为                                                                 |
| ------------------------------------ | ------------------ | -------------------------------------------------------------------- |
| 页面加载失败、无权限、空数据         | 当前内容区域       | 作为页面状态持续展示，提供明确的下一步                               |
| 字段格式、必填项校验失败             | 对应字段下方       | 字段设置 `aria-invalid=true`，提示与字段通过 `aria-describedby` 关联 |
| 保存、发布、上传、复制、连接测试结果 | 视口右上角         | 使用 `FeedbackNotice placement="viewport"`，滚动到任何位置都可见     |
| 高风险操作确认                       | 确认弹层           | 必须保留原因、影响说明和二次确认；反馈提示不能替代确认               |
| 弹层内部提交失败                     | 弹层或操作面板内部 | 保留用户已输入内容，错误紧邻当前操作上下文                           |

## 交互规则

1. 同一页面同时只显示一个主操作反馈，新的反馈替换旧反馈。
2. 错误默认持续展示，直到用户关闭、修正字段或重新操作。
3. 成功提示必须支持主动关闭；不得在用户尚未读完时强制消失。
4. 视口反馈不得抢夺输入焦点，但必须使用正确的无障碍语义：错误为 `role="alert"`，成功为 `role="status"`。
5. 字段校验不能只显示在页面顶部。触发提交时应保持操作区域可见，并在错误字段附近给出具体修正方式。
6. 禁止使用浏览器原生 `alert`、`confirm` 表达业务反馈。

## 组件使用

```tsx
<FeedbackNotice
  kind="error"
  message="保存失败，请检查配置后重试"
  placement="viewport"
  onDismiss={() => setFeedback(null)}
/>
```

页面级加载异常继续使用内容区域内的 `error-banner`；表单字段错误使用 `.field-error`。

## 统一表单校验机制

所有可提交表单都应同时表达字段错误与错误摘要：

```tsx
<FormValidationSummary
  errors={[
    {
      field: "修改原因",
      message: "请填写至少 3 个字符的修改原因。",
      targetId: "change-reason",
    },
  ]}
/>
```

- 每个错误字段必须有稳定的 `id`、`aria-invalid="true"` 和 `aria-describedby`。
- 提交时允许用户点击提交按钮触发校验；仅在请求处理中禁用提交按钮。
- 校验失败后调用 `focusFirstInvalidField`，聚焦并滚动到第一个错误字段。
- 摘要中的字段名必须可点击，并定位到同一个 `targetId`。
- 下拉框统一使用设计系统 `SelectField`，业务页面不得直接渲染原生 `<select>`。
